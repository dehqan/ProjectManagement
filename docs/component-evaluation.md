# کارت‌های ارزیابی مؤلفه‌های بسته‌بندی

طبق D-17 هر مؤلفهٔ کاندید باید از پنج محور عبور کند. این فایل هنوز خالی است؛ کارت‌ها در مرحلهٔ تحقیق پر می‌شوند. هیچ نامی در `scope-proposal.md` «انتخاب» نیست تا کارتش این‌جا کامل شود.

## قالب کارت

| محور | پرسش | نتیجه | شواهد |
|---|---|---|---|
| ۱. فارسی و راست‌به‌چپ | رابط و محتوا فارسی و RTL را درست نشان می‌دهد؟ تقویم شمسی؟ | | |
| ۲. سازگاری کنار هم | با مؤلفه‌های دیگر بسته تداخل نسخه، پورت یا منبع ندارد؟ | | |
| ۳. ورود و دسترسی | ورود یکپارچه با سامانهٔ ما؟ دسترسی از مدل سازمان و اشتراک ما (D-16) قابل‌همگام‌سازی است؟ | | |
| ۴. رابط‌های یکپارچگی | رویداد و Webhook برای تغییرات؟ تعبیه در رابط ما؟ API نسخه و محتوا؟ پیوند عمیق دوطرفه؟ | | |
| ۵. عملیات | نصب، ارتقا، پشتیبان و مقیاس توسط ما شدنی است؟ نیاز سخت‌افزاری؟ | | |

نتیجهٔ کلی: **عبور / رد / مشروط** + گزینهٔ جایگزین اگر رد شد.

## کارت‌ها

کارت کامل هر حوزه در `components/` است.

| حوزه | کاندیدها | پیشنهاد | نتیجه | شرط اصلی | کارت |
|---|---|---|---|---|---|
| ویرایشگر سند Office (DMS-06) | OnlyOffice، Collabora | **Collabora Online** | مشروط | آزمون ۴۰ تا ۶۰ فایل واقعی فارسی (جدول RTL، فونت، نیم‌فاصله) با رفت‌وبرگشت به Word/Excel. OnlyOffice رد (باگ‌های باز RTL). | `components/doc-editor.md` |
| تماس زنده (COL-11) | Jitsi، LiveKit | **LiveKit** | مشروط | آزمون میدانی TURN/TLS روی ۴۴۳ از مرکز دادهٔ داخلی روی سه اپراتور همراه؛ رابط فارسی را خودمان می‌سازیم. Jitsi گزینهٔ دوم. | `components/meetings.md` |
| OCR فارسی (DMS-11) | Tesseract، PaddleOCR | **Tesseract با مدل تنظیم‌شدهٔ فارسی** | مشروط | خطای نویسه حداکثر ۲٪ روی ۲۰۰ تا ۳۰۰ صفحه سند واقعی؛ مدل رسمی `fas` و PaddleOCR رد. | `components/ocr.md` |
